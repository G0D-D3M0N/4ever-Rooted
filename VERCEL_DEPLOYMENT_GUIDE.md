# Vercel + GitHub + GoDaddy + Clerk Deployment Guide

This guide is the exact production setup for this repository.

Function entrypoint used by Vercel: `api/index.mjs` (wrapper) -> `dist/server.cjs` (generated by build).

## 1) Prepare and push code

Run locally:

```bash
npm install
npm run build
git add script/build.ts server/vercel.ts server/storage.ts server/db.ts vercel.json VERCEL_DEPLOYMENT_GUIDE.md
git commit -m "Fix Vercel API runtime and harden production DB handling"
git push origin main
```

## 2) Import repository in Vercel

1. Open Vercel dashboard.
2. Create/import project from your GitHub repository.
3. Use these settings:
   - Framework Preset: `Other`
   - Build Command: `npm run build`
   - Output Directory: `dist/public`
   - Install Command: `npm install --include=dev`

## 3) Add required Vercel environment variables

Set these in **Project Settings -> Environment Variables** for `Production`, `Preview`, and `Development`:

- `TURSO_DATABASE_URL` = your Turso libsql URL (e.g. `libsql://...turso.io`)
- `TURSO_AUTH_TOKEN` = your Turso auth token
- `CLERK_SECRET_KEY` = Clerk backend secret key
- `VITE_CLERK_PUBLISHABLE_KEY` = Clerk frontend publishable key
- `CLERK_ADMIN_USER_IDS` = comma-separated Clerk user IDs for admin access
- `CUSTOM_DOMAIN` = your apex domain only (example: `example.com`)

Optional compatibility fallback:
- `DATABASE_URL` (only if you use this naming in other environments)

## 4) Redeploy after env vars are saved

In Vercel Deployments:
1. Open latest deployment.
2. Click **Redeploy** and choose **Use existing Build Cache = off** for the first clean deploy after this fix.

## 5) Connect GoDaddy domain

### Option A (recommended): delegate nameservers to Vercel

In GoDaddy domain settings, set nameservers to:

- `ns1.vercel-dns.com`
- `ns2.vercel-dns.com`
- `ns3.vercel-dns.com`
- `ns4.vercel-dns.com`

Then in Vercel -> Project -> Domains:
- Add `yourdomain.com`
- Add `www.yourdomain.com`

### Option B: keep GoDaddy DNS

Create these DNS records in GoDaddy:
- `A` record for `@` -> `76.76.21.21`
- `CNAME` record for `www` -> `cname.vercel-dns.com`

Then add both domains in Vercel.

## 6) Configure Clerk for your deployed domains

In Clerk dashboard:
1. Add your Vercel domain and custom domain to allowed origins/redirect URLs.
2. Verify publishable and secret keys are from the same Clerk instance.
3. Ensure the same keys are set in Vercel env vars.

## 7) Verify API and database in production

After deployment, test:

- `https://<your-domain>/api/resources`
- `https://<your-domain>/api/roadmaps`
- `https://<your-domain>/api/stats`

Expected:
- HTTP 200 for each endpoint
- Non-empty arrays/counts if your Turso DB already has data

## 8) If API still shows empty data

1. Confirm Vercel env var values are from the correct Turso database (not a different DB/branch).
2. From local machine against the same DB:
   - `npm run db:push` (ensures schema)
   - `npm run seed` (if you want to seed baseline data)
3. Redeploy in Vercel and re-test endpoints.

## 9) Why this repo previously failed on Vercel

The API function was loading dev tooling (`vite`/`rollup`) at runtime in serverless, causing 500 errors.  
This repository now uses a dedicated serverless entry (`server/vercel.ts`) and a hardened parser for legacy DB JSON fields, so `/api/resources` and `/api/stats` stay stable.
